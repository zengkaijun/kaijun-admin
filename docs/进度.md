### T1 工程骨架

**任务**：搭起可运行的前后端骨架与登录。  
**前置**：技术方案已确认。  
**做法**（给 Cursor 的提示词）：

```text
【背景】凯俊后台：IT 产品经理个人工作台（以项目为主线），MVP 开发起点，本任务只搭骨架与登录，不做业务模块。
【任务】在项目根目录初始化可运行工程：
1. 创建 server/（Node + Express，ESM）：/api/auth/login、/api/auth/logout、/api/auth/me；bcryptjs 密码校验；cookie-session；首个管理员账号从 .env 读 ADMIN_USER/ADMIN_PASSWORD_HASH 或首次启动用 seed 脚本哈希写入（密钥不进 git）。
2. 创建 Vite 前端（React）：登录页、登录后占位首页；/api 代理到 Express。
3. 根 package.json 提供 dev（并行 server+web）、build、start；.gitignore 忽略 node_modules、.env、data、dist；提供 .env.example。
4. SQLite：server/db.ts 打开 data/app.db，建 users 表（尚可无 projects）。
【约束】遵守 AGENTS.md 与 .cursor/rules；只加骨架必需依赖并各写一句理由；禁止硬编码密钥；不实现项目/跟进等业务。
【验收】
1. npm run dev 后浏览器能登录并看到占位页；错误密码有提示；
2. 登出后刷新需重新登录；
3. data/*.db 与 .env 不被 git 跟踪；
4. 未登录访问 /api/auth/me 返回 401。
【完成后】列出改动文件清单，并告诉我如何运行验证。
```

**验收**：提示词【验收】四条；用户回传运行结果/截图。

### T3 跟进循环 + 待跟进 + 状态动作

**任务**：跟进时间线、下次跟进日、待跟进列表、定性/重启。  
**前置**：T2。  
**做法**：

```text
【背景】凯俊后台核心交互：项目跟进循环（PRD v0.3）。
【任务】
1. follow_ups 表 + GET/POST /api/projects/:id/followups（含 occurred_at、channel、content、next_follow_up_at）。
2. PATCH 项目时合法更新 next_follow_up_at；GET /api/projects?due=today 返回 status∈(following,waiting) 且 next_follow_up_at≤今天的项目。
3. POST /api/projects/:id/actions：restart | lose | win | pause | delay；按技术方案状态机校验；win 时 is_deal=yes，lose 时 is_deal=no。
4. 前端项目详情：跟进表单（本次结果+下次跟进日）、时间线、操作按钮（无法成交/成交/暂停/延后/重新启动）；列表待跟进日醒目标记。
【约束】历史跟进只增不删；不吞错误；遵守 AGENTS.md。
【验收】
1. 记跟进+明日→出现在待跟进；再记+3 天→两条时间线且日期正确；
2. 无法成交后退出待跟进；重新启动后回到跟进且历史完整；
3. 成交写入金额与 is_deal；
4. 非法状态流转返回 400 且前端有提示。
【完成后】列出改动文件清单，并告诉我如何运行验证。
```

**验收**：PRD 跟进循环五条 Given/When/Then。
