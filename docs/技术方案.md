# 凯俊后台 技术方案

> 对应 PRD：`docs/PRD.md` v0.3（已确认）  
> 状态：**v2 修订稿 · 待用户确认**（按用户指定：PHP + MySQL 最新 + Docker + 便于 GitHub 多机开发）

## 目标（一句话）

以 **Docker Compose** 一键起本地开发环境，**PHP 后端 + MySQL** 支撑以项目为主线的 MVP，并保证仓库克隆后即可在其他电脑继续开发，架构上为后续模块/部署扩展留口。

## 硬约束（用户拍板）

| 约束 | 落实 |
|---|---|
| 用上 Docker Desktop | `docker-compose.yml` 托管 MySQL / PHP / 前端开发服务 |
| 后端语言 PHP | **Laravel**（主流、扩展与资料最多） |
| 数据库 MySQL，版本最新 | 镜像 `mysql:9`（创新线）；若遇扩展兼容问题回退 **`mysql:lts`（8.4）** |
| 本地开发 | 默认只绑 `127.0.0.1` |
| 上传 GitHub 多机开发 | 完整 README、`.env.example`、无密钥入库、卷与缓存 gitignore |

## 选型

| 层 | 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| 应用框架 | **Laravel 12 + PHP 8.4** | 生态成熟、Eloquent、队列/邮件等扩展顺手、Cursor 资料多 | 比 Slim 重一点 | **采用**（扩展迭代优先） |
| 微框架 Slim | 更轻 | 自建认证/校验/迁移成本高 | 不选 |
| API 形态 | **前后端分离 REST API** | 以后可加小程序/脚本；前端独立 | 多一个跨域/代理配置 | **采用** |
| SPA | **Vite + React 18 + Ant Design 5** | 与 v1 方案一致、后台组件齐 | — | **采用** |
| ORM | Eloquent | 迁移、关系、查询构造器 | — | **采用** |
| 认证 | Laravel Sanctum（Personal Access Token 或 Session Cookie） | 官方、可扩展到多端 | MVP 可用简单 session cookie | **默认 Session Cookie**；预留 Sanctum 升级 |
| 本地编排 | **Docker Compose** | MySQL 与 PHP 版本锁定、换机一致 | 镜像拉取需网络 | **采用** |
| 生产以后 | 同 compose 可加 nginx/caddy、PHP-FPM | 与开发同构 | — | 本期不做公网 |

### 依赖原则

- 业务代码只依赖 Laravel 官方与极少数通用包；**每加一个 composer/npm 包必须写一句理由**。  
- 不为「以后可能」上微服务、Redis、K8s；扩展点用清晰模块边界即可。

## Docker 架构

```text
docker compose
├── db      image: mysql:9（或 mysql:lts）
│           卷: mysql-data:/var/lib/mysql
│           端口: 127.0.0.1:3306:3306
├── app     image: 自定义 php:8.4-cli / php:8.4-fpm + pdo_mysql, mbstring, zip 等
│           工作目录: /var/www/html  ← 挂载仓库
│           跑: php artisan serve 或 php-fpm+nginx（开发用 artisan serve 足够）
│           端口: 127.0.0.1:8000:8000
└── web     镜像: node:22（或 20）用于 Vite dev
            挂载前端目录，端口 127.0.0.1:5173:5173
            proxy /api → app:8000
```

**命令（写入 README）**：

```bash
docker compose up -d
# 首次：复制 .env.example → .env，生成 APP_KEY，migrate，建管理员
docker compose exec app php artisan migrate
docker compose exec app php artisan db:seed   # 或自定义 admin seeder
```

换电脑：`git clone` → 建 `.env` → `docker compose up -d` → migrate/seed。

### 仓库与 GitHub

| 进 git | 不进 git |
|---|---|
| `docker-compose.yml`、`Dockerfile`（如有） | `.env` |
| 代码、迁移、种子、README | `vendor/`、`node_modules/` |
| `.env.example`（占位符） | `storage/logs/*`、`data/` |
| 前端源码与锁文件 `package-lock.json` | 本地数据库卷 |

`.env.example` 必含：`APP_KEY=`、`DB_HOST=db`、`DB_DATABASE=`、`DB_USERNAME=`、`DB_PASSWORD=`、`SESSION_*`。  
**密钥零入库**：真实口令只在本机 `.env`。

## 数据模型（与 PRD v0.3 对齐）

沿用原表结构语义，改为 Laravel migrations + Eloquent；日期用 `DATE`/`DATETIME`，金额 `DECIMAL(12,2)`。

- `users` — 管理员  
- `projects` — 主线：`stage`、`is_deal`、`status`、`next_follow_up_at`、金额、客户字段（依附项目）  
- `follow_ups` — 跟进循环（只增不删）  
- `tasks`、`time_entries`、`research_notes`、`scripts`  

**状态机**与 v1 相同（后端用 PHP enum / 验证规则强制）：

```text
following|waiting|paused|delayed ⇄ 各动作
lost|paused|delayed --restart--> waiting
--win--> won + is_deal=yes
--lose--> lost + is_deal=no
待跟进: status IN (following,waiting) AND next_follow_up_at <= CURDATE()
```

## API（`routes/api.php`，前缀 `/api`）

与 v1 表一致：`auth/*`、`projects`、`projects/{id}/followups`、`projects/{id}/actions`、`summary`、`tasks`、`times`、`research`、`scripts`。

- 登录：`POST /api/auth/login` → session（Sanctum 亦可，实现时二选一写明）。  
- 写接口：登录中间件 + FormRequest 校验。  
- CORS：开发仅允许 `http://127.0.0.1:5173` / `localhost:5173`。

## 扩展点（只设计不实现）

| 后续 | 预留方式 |
|---|---|
| 多用户/角色 | `users.role` 预留列可空；中间件结构先分 `auth` |
| 对外 API / 小程序 | 已分离 REST，可加 token |
| 队列通知（跟进提醒） | Laravel 队列驱动先 `sync`，以后改 redis |
| 报价单附件 | `projects` 或 `media` 表后补 |
| 部署 VPS | compose 增加 nginx + `php-fpm`，不变业务代码 |

**YAGNI**：以上不做本期代码，只保证表结构与路由不挡路。

## 风险与回退

| 风险 | 回退 |
|---|---|
| `mysql:9` 与 PHP 镜像扩展不兼容 | 改 `mysql:lts`（8.4），一行 compose |
| Laravel 首次上手偏重 | 任务拆细；生成物（迁移/控制器）由 Cursor 按任务卡产出 |
| Windows 路径/权限（storage、vendor） | compose 内统一 Linux 路径；文档写明 `vendor` 在容器内 install |
| GitHub 含密钥 | pre-commit 靠 review + `.env` gitignore；可选 gitleaks 后补 |
| `artisan serve` 性能 | 仅开发可接受 |
